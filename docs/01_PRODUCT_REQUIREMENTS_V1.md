## 2. 产品目标与目标用户

### 2.1 产品目标

本产品是一个仅供个人本地研究使用的 A股价值投资研究与筛选工具。它帮助用户在本地 Windows 中文桌面浏览器环境中完成四类核心工作：

1. 以当前数据为基础进行价值筛选
2. 对单只股票做以财务与估值为核心的研究
3. 通过 CLI 与 OpenCode 完成全部核心写操作与运维操作
4. 在免费数据约束下完成初始化、更新、修复、归档、备份与恢复

### 2.2 目标用户

目标用户是单人使用者，特征如下：

- 主要研究中国 A 股
- 重视基本面、估值、安全边际与股东回报
- 接受本地部署与命令行操作
- 不需要多人协作、移动端、登录或公网服务

### 2.3 成功定义

V1 成功的标志不是平台级覆盖率，而是：

- 用户可以在本地稳定完成当前筛选与单股研究
- 数据缺口、近似值、失败任务与来源冲突都被明确标记
- 用户可以通过 CLI 可控地完成维护、修复、归档、备份与恢复
- 全流程不依赖付费数据源，不包含登录与公网托管

## 3. 硬约束

### 3.1 环境与访问边界

- 仅支持个人本地 Windows 中文桌面环境
- 仅要求支持当前版本的 Chrome 与 Edge 桌面浏览器
- 仅通过 localhost 使用，不提供公网访问
- 不需要用户账户、登录、权限体系或多用户协作
- 不面向移动端

### 3.2 成本边界

- 完全免费是硬约束
- 可接受免费注册、免费 token 或免费额度
- 不接受任何必须持续付费才能满足 V1 核心流程的数据依赖

### 3.3 用途与分发边界

- 仅限个人本地研究用途
- 不支持数据再分发、二次售卖或对外提供数据服务
- 不承诺替代交易所、公告平台或商业数据库的法定披露职责

### 3.4 范围边界

- 只做当前 A股价值研究与当前筛选
- 不做历史筛选、历史行业排名、回测、交易、组合跟踪、自动提醒、新闻、市场总览或多股对比
- 不做内建 OCR
- 不做自动执行已保存筛选规则

## 4. 术语表

- `strict`：可直接按约定口径计算或核对的值
- `approximate`：来自免费源下的可用近似值，允许展示与使用，但必须明确标记
- `missing`：当前无法提供的值或字段状态
- `latest_restated`：基于最新重述口径的当前值与历史序列，是当前指标、历史图表与复合指标的默认口径
- `as_reported`：公司在原始披露时点的原始口径，仅在可获得时保留用于溯源与差异展示
- `historical_capable`：某个指标或复合指标允许生成可信历史序列
- `current_only`：某个指标只能用于当前时点，不允许承诺历史序列
- `schema_version`：CLI 与 OpenCode JSON 协议的模式版本号，按主版本兼容规则管理
- `plan_id`：危险操作的计划令牌，只能在计划有效期内用于确认执行
- 当前基础股票池：当前上市股票中，应用用户当前可见的 ST、停牌与上市年限预设开关后形成的排名基准集合；临时筛选条件不得改变该集合
- 最小核心财务集：最新可得合并报表中，计算第 10.1 节至第 10.5 节全部适用内建指标所需的标准化字段，以及第 6.6 节要求的适用金融行业字段
- raw：未复权日线价格
- qfq：前复权日线价格
- ST 或 *ST：风险警示股票

## 5. 页面范围

V1 只有以下四个页面：

1. 筛选页，默认首页
2. 自选列表页
3. 个股详情页
4. 只读数据状态页

以下页面明确不做：

- 市场总览页
- 首页资讯流
- 组合管理页
- 交易页

## 6. 市场与数据范围

### 6.1 市场覆盖

- 上交所与深交所是主覆盖范围
- 北交所为最小可用覆盖，不追求与沪深完全同等深度
- 当前筛选股票全集只包含当前上市股票
- 对当前上市沪深股票，日线历史的目标范围是上市以来全部可得数据；北交所历史按可得性尽力回填

### 6.2 北交所最低要求

北交所 V1 至少满足：

1. 日线价格与成交量数据
2. 核心且最新的基本面字段
3. 当前筛选可用

北交所长尾字段、早期历史、行业特有字段允许部分缺失，但必须明确标记为 `missing` 或 `approximate`。

### 6.3 当前研究与当前排名范围

- 只支持当前筛选
- 只支持当前基础股票池内的全市场排名
- 只支持当前基础股票池内的申万一级与二级行业排名
- 不支持历史行业排名
- 不支持历史筛选结果回放
- 不支持回测

### 6.4 价格与公司行为数据

V1 必须覆盖：

- raw 日线
- qfq 日线
- 分红
- 送股
- 转增
- 配股
- 拆股与并股
- 除权除息日期
- 股本变化
- 最近收盘价与对应日期

最近收盘价允许陈旧，但必须显示价格日期。

日线与估值更新以最近完成的交易日收盘数据为准，不要求盘中实时更新。

### 6.5 财务结构化覆盖

- 结构化财务数据目标覆盖从 2010Q1 起
- 2010Q1 之前为尽力而为，不纳入刚性验收
- 默认使用合并报表口径
- 目标结构化范围包括资产负债表、利润表与现金流量表的标准化科目
- 全部已完成标准化的报表科目必须可供 DSL 与 CLI 查询使用
- 必须同时支持累计值与单季度值语义
- 展示默认以年度为主，允许切换到季度与 TTM

### 6.6 金融行业边界

在免费数据约束下，V1 的强制性金融行业结构化要求仅包括：

- 沪深银行的核心一级资本充足率、一级资本充足率、资本充足率、不良贷款率、拨备覆盖率
- 沪深证券公司的风险覆盖率

银行、证券公司与保险公司仍然必须进入当前股票全集，并可使用适用的通用财务指标；行业特有字段不适用时按 `null` 与原因码处理。

以下能力仅属尽力而为或 PDF 辅助，不属于 V1 刚性验收：

- 银行净息差
- 证券公司净资本
- 保险公司偿付能力
- 北交所行业特有监管指标

### 6.7 最小可用初始化的数据定义

产品进入可筛选状态前，至少必须具备：

1. 当前上市股票全集与默认基础股票池所需的 ST、停牌、上市日期字段
2. 每只股票最近一个可得交易日的 raw 收盘价、成交量与价格日期
3. 每只股票最近 5 年的可得 raw 与 qfq 日线；上市未满 5 年时覆盖上市以来全部可得日线
4. 每只股票的最小核心财务集；字段不适用或免费源确实不可得时，必须提供 `null`、原因码与置信度，不得用默认值替代
5. 当前申万一级与二级归属；缺失时按第 12.4 节处理，不阻止股票参与全市场排名

以上定义统一作为第 7 章、第 19 章与第 20 章所称“最小可用初始化”或“最新核心财务”的验收口径。

## 7. 数据生命周期

### 7.1 初始导入原则

初始数据导入是一项一次性的完整性建设工程，不要求第一次使用前就完成全历史、全字段、全市场一次到位。

### 7.2 分阶段可用性

V1 必须优先保证以下顺序：

1. 当前上市股票全集可见
2. 第 6.7 节定义的最小核心财务集与相关内建指标可用
3. 近 5 年价格可用
4. 其余历史回填继续进行

在回填未完成期间，界面必须可见当前覆盖状态与未完成范围。

### 7.3 启动时检查

每次启动只进行简单增量检查，范围仅包括：

- 是否出现新的交易日
- 是否出现新的公告或财报
- 是否存在待重试任务

允许配置可选定时任务，但默认不要求平台级调度系统。

### 7.4 失败处理

任一增量更新失败时：

1. 保留旧值，不以空值覆盖旧值
2. 生成明确的重试列表
3. 生成明确的缺失列表
4. 在数据状态页可见失败摘要

V1 不引入平台级覆盖阈值、每日快照放行制度或发布门禁。

### 7.5 保留策略

- 显式保存的筛选结果引用必须长期保留，除非用户删除
- 未被任何保存结果引用的中间快照可在 30 天后清理
- 不承诺每日统一发布平台级快照

### 7.6 与筛选的耦合限制

数据同步、增量检查与历史回填都不得自动运行任何已保存筛选规则。

## 8. 财务语义

### 8.1 默认口径

除专门说明外，当前指标、历史图表与全部复合指标都以 `latest_restated` 为统一默认口径。

### 8.2 `as_reported` 的边界

`as_reported` 仅在可获得时用于：

1. 溯源展示
2. 字段级差异对照
3. 说明某指标为何与当前重述值不同

V1 不承诺：

- 全市场完整 `as_reported` 版本链
- 对历史所有原始版本逐期重算全部复合指标
- 免费源条件下的官方双版本完整覆盖

必须明确说明：免费数据源不支持对完整 `as_reported` 版本链作出刚性保证。

### 8.3 估值与市场指标计算原则

- PE、PB、PS、PCF 等核心估值指标，以系统内部计算结果为准
- 外部来源自带的估值值仅作交叉核对，不作为产品最终结果

## 9. 可靠性、置信度、空值、冲突与人工覆写

### 9.1 置信度模型

所有可展示值都必须具备以下之一：

- `strict`
- `approximate`
- `missing`

界面必须提供仅查看 `strict` 的开关。

### 9.2 不允许的行为

- 不允许用插值、均值替代、回归推断等方式填补缺失值
- 不允许把没有业务意义的值伪装成零值或默认值

### 9.3 空值语义

当字段缺失、无效、口径不适用、无法比较或无业务意义时：

1. 返回 `null`
2. 返回机器可读原因
3. 在界面上显示人类可读解释

### 9.4 来源冲突

- 多来源冲突时，以主来源优先
- 同时保留原始来源值、抓取时间与来源标识，用于溯源与排障

### 9.5 人工覆写

人工覆写必须满足：

- 与原始抓取值分离存储
- 可审计
- 可回滚
- 可显示覆写原因
- 可预览覆写影响面

人工覆写不得静默覆盖原始来源值。

## 10. 内建指标目录

V1 的内建指标必须至少包含以下字段：

### 10.1 估值

- 总市值
- 流通市值
- PE-TTM
- PB-MRQ
- PS-TTM
- PCF-TTM
- 股息率

### 10.2 盈利能力与质量

- ROE
- ROA
- 毛利率
- 净利率
- 投入资本回报率
- 经营现金流与净利润比值

### 10.3 成长

- 营业收入同比增长率
- 归母净利润同比增长率
- 扣非归母净利润同比增长率
- 营业收入 3 年与 5 年 CAGR
- 归母净利润 3 年与 5 年 CAGR
- 扣非归母净利润 3 年与 5 年 CAGR

### 10.4 安全性

- 资产负债率
- 流动比率
- 速动比率
- 有息负债
- 利息保障倍数
- 商誉占比

### 10.5 股东回报

- 分红率
- 每股股息
- 连续分红年数

### 10.6 行情与技术统计

- MA5、MA10、MA20、MA60、MA120、MA250
- 可指定区间收益率
- 年化波动率
- 最大回撤
- 平均成交量
- 换手率

内建指标可被 DSL、筛选页、自选列表与个股详情复用。除内建指标外，DSL 还必须可直接调用全部标准化财务字段与已注册行业特有字段。

## 11. 受控 DSL

### 11.1 范围

V1 只提供受控 DSL，不提供任意脚本能力。DSL 允许使用：

1. 数值与布尔表达式
2. 内建指标
3. 全部标准化报表字段
4. 已注册行业特有字段
5. 版本锁定的复合指标

### 11.2 支持的运算与派生

DSL 必须支持：

- TTM
- YoY
- QoQ
- 指定年数的 CAGR
- 指定期数的平均值、最大值与最小值
- 指定期数的 rolling 运算
- 指定期数的 lag
- 当前基础股票池内的全市场排名
- 当前基础股票池内的申万一级与二级排名
- 百分位
- Z-score
- 归一化

所有横截面函数都自动标记为 `current_only`。

### 11.3 历史能力判定

系统必须自动为每个表达式推导 `historical_capable` 或 `current_only`。用户不能强制一个本质上只能当前计算的表达式去生成历史序列。

### 11.4 维度校验与空值规则

DSL 必须具备强维度校验，至少防止：

- 百分比与绝对金额直接比较
- 累计值与单季度值混用
- 当前横截面排名被误当成历史序列
- 单位不兼容字段相互比较

DSL 运算必须遵守第 9 章空值语义，不得自行补值。

当分母为零、估值对亏损公司无业务意义、历史期数不足或任一必要字段缺失时，结果必须为 `null` 并返回稳定原因码。

### 11.5 简写、元数据与发布流程

- 允许用户使用简写，但所有简写必须展开为明确字段标识后再保存
- 流量与盈利能力字段的简写默认展开到 TTM 口径；资产负债表时点字段默认展开到最新报告期口径
- 保存前必须向用户展示完整展开结果，例如将简写明确展示为对应的 TTM 或最新报告期字段标识
- 每个已发布表达式都必须带中文描述与方向定义
- 生命周期必须是 草稿、校验、单股预览、小样本预览、发布
- 已发布版本不可变更，修改必须生成新版本
- 依赖必须版本锁定，系统必须拒绝循环依赖

### 11.6 禁止项

DSL 不支持：

- 自定义函数
- Python
- SQL
- 任意脚本执行

## 12. 筛选页

### 12.1 页面定位与恢复

筛选页是默认首页。若存在最近草稿，则自动恢复最近草稿；若不存在，则显示空白草稿。临时运行结果不自动保存。

### 12.2 规则表达与运行

- 提供可视化 AND 或 OR 规则编辑器
- 逻辑嵌套最多 3 层
- 单个条件可比较常量、区间或另一兼容指标
- 只允许用户自建规则，不提供预设模型分类
- 规则编辑必须版本化
- 已保存规则必须锁定其引用的指标版本；修改规则或升级指标引用时必须生成新规则版本
- 只支持手动运行
- 每次运行都以最新可用数据为准

### 12.3 默认股票池

默认基础股票池必须排除：

- ST 与 *ST
- 停牌股票
- 上市未满 1 年股票

这些条件必须可见且可切换。切换后，市场排名与行业排名的分母也必须同步变化。

排名分母只由当前基础股票池预设决定。用户随后添加的估值、财务或复合指标筛选条件不得重新计算或缩小排名分母。

### 12.4 排名缺失规则

- 若股票缺少当前申万归属，则行业排名返回 `null`
- 即使行业排名为 `null`，全市场排名仍然可用

### 12.5 结果展示与保存

筛选结果必须支持：

- 明确列配置
- 明确多字段排序
- 只对入选股票提供入选解释
- 不提供未入选股票诊断
- 保存结果时标题必填，备注可选
- 显式保存的结果必须保留本次数据日期、规则版本、指标版本、排序、列配置与置信度信息
- 导出的 CSV 必须包含数据日期、规则版本、指标版本、置信度与必要来源信息
- 结果可直接加入自选列表

临时运行不进入运行历史；只有显式保存结果或导出时，才保留用于复现本次结果的数据引用。

### 12.6 性能要求

在 5000 支以上股票、10 到 20 个条件的场景下，手动运行当前筛选的结果返回时间应不超过 5 秒。

## 13. 自选列表

自选列表必须支持：

- 分组
- 排序
- 自定义列
- 手动保留
- 手动移除
- 记录来源于哪次筛选或哪条规则

自选列表明确不支持备注、目标价、预警或自动提醒。

## 14. 个股详情页

个股详情页必须支持：

- 股票代码、名称、拼音、最近收盘价与价格日期
- 日 K 线、成交量、均线叠加、raw 与 qfq 切换、缩放与十字光标
- 估值、盈利、成长、安全与股东回报摘要
- 财务趋势预设视图与自定义数值指标视图
- 年度默认视图，以及季度与 TTM 切换
- 若指标为 `historical_capable`，则默认展示 5 年，并允许切换 1 年、3 年、5 年、10 年、全部
- 若指标为 `current_only`，则明确说明只能做当前展示，不生成伪历史图
- 关键字段与关键原始材料的溯源信息
- 已恢复本地 PDF 的浏览器打开能力

指标溯源至少必须包含报告期、生效日期、数据版本、来源、价格日期、置信度、公式，以及可获得时的 `as_reported` 与 `latest_restated` 字段差异。

原始报表大表格不在网页展示，但全部标准化报表字段必须可供计算与 CLI 查询。

个股详情页明确不支持网页原始报表大表格与多股票对比。

## 15. 只读数据状态页

数据状态页只用于展示状态，不提供写操作。至少必须可见：

- 最近一次成功更新的时间
- 股票覆盖状态
- 财务覆盖状态
- 历史回填状态
- 重试列表摘要
- 缺失列表摘要
- PDF 解析失败任务摘要
- 最近备份与归档摘要

页面不得直接执行更新、修复、恢复、发布、删除或清理。所有此类操作只能通过 CLI 完成。

## 16. CLI 与 OpenCode

### 16.1 范围与协议

所有核心写操作与运维操作必须可由 CLI 完成，OpenCode 通过同一正式 JSON 协议调用。协议必须包含 `schema_version`，并按主版本兼容规则管理。

CLI 的核心范围至少包括：

- 发现字段、指标、函数、原因码与当前能力
- 创建、校验、预览、发布与版本化复合指标
- 创建、版本化与手动运行筛选规则
- 保存结果、导出结果与管理自选列表
- 初始化、增量更新、诊断、重试、切换来源与指定范围重抓
- 查看冲突、提交人工校正与撤销人工覆写
- 归档、验证、清理计划、备份、恢复与一键启动

### 16.2 交互与稳定性要求

- CLI 必须支持非交互运行
- CLI 必须提供机器可读的 `schema`、`capabilities` 与 `examples`
- 必须提供面向 OpenCode 的 skill 说明
- 错误输出格式与原因格式必须稳定
- 不允许通过 CLI 直接修改数据库文件或应用代码

### 16.3 危险操作两段式确认

危险操作必须采用计划与确认分离：

1. 第一步返回计划摘要与 `plan_id`
2. 第二步在有效期内基于 `plan_id` 确认执行

`plan_id` 有效期固定为 15 分钟，过期后必须拒绝执行。

### 16.4 禁止项

- 不提供内建 AI 或模型 API
- 不提供自由代码执行
- 不提供直接数据库或代码突变入口

## 17. PDF 解析失败与结构化校正

当 PDF 解析失败或字段不可信时，系统必须生成可机器处理的失败任务，而不是静默忽略。

V1 必须支持受控 JSON 校正模板。模板至少包含：

- 公告标识
- 对应 PDF 的哈希
- 页码
- 报告期
- 单位
- 校正原因
- 拟写入字段与数值

校正流程必须是 草稿、校验、影响预览、确认发布。V1 不提供内建 OCR，但允许人工或外部 AI 生成校正模板，产品本身只负责校验、预览与发布。

## 18. 归档、备份、恢复与凭据

### 18.1 冷热分层

- 本地结构化数据属于热数据
- 公共 PDF、原始响应与备份包属于冷归档数据

### 18.2 归档与恢复

- 执行冷归档功能时，用户必须配置一个本地目标目录；推荐将该目录设置为百度网盘等云盘客户端的同步目录
- 产品只负责向本地目标目录写入归档包与校验清单，不登录云服务、不调用云盘 API，也不要求云盘客户端在日常研究时在线
- 只有在归档验证成功后，才允许人工触发本地清理
- 恢复只能通过 CLI
- 当网页需要的 PDF 尚在冷归档中时，网页必须显示归档位置、校验信息与对应 CLI 恢复指引
- 恢复完成后，如包含 PDF，用户可在浏览器中打开恢复出的 PDF

### 18.3 加密与保留

- 公共数据可以不加密
- 个性化数据必须加密；个性化数据至少包括复合指标、筛选规则、自选列表、显式保存结果、人工覆写与用户配置
- 至少保留最近 3 套全量备份，每套全量备份可带增量链
- 个性化备份使用用户口令保护，并生成单独保管的离线恢复密钥
- 所有凭据不得进入备份与导出文件，且必须采用 Windows 凭据保护机制存储

## 19. 性能与可用性

- V1 必须支持一键启动
- 只要求当前版本 Chrome 与 Edge 桌面浏览器，不要求手机或平板适配
- 启动后的优先目标是尽快进入可研究状态，而不是等待全量历史回填结束
- 初始最小可用能力必须先保证 股票全集、最新核心财务、近 5 年价格，然后继续历史回填
- 界面必须可见当前覆盖状态与回填状态
- 允许使用最近一个可得收盘价作为当前研究价格前提，但必须显示价格日期
- 数据同步绝不能自动运行任何已保存筛选规则

### 19.1 筛选性能验收环境

5 秒筛选目标按以下统一条件验收：

- 在用户正式使用的目标 Windows 主机上执行，并在技术规划开始时记录该主机的 CPU、内存与磁盘类型
- 使用本地热数据，不包含首次启动、历史回填、数据抓取、备份或归档耗时
- 使用不少于 5000 支股票、20 个条件、至少一个复合指标和一次当前行业排名的固定验收夹具
- 先执行一次不计时预热，再连续执行 10 次
- 10 次中至少 9 次在 5 秒内返回完整结果

## 20. V1 四条验收流程

### 20.1 验收流程一：当前筛选

前置条件：本地已完成第 6.7 节定义的最小可用初始化。

通过标准：

1. 打开产品默认进入筛选页
2. 最近草稿可自动恢复，否则显示空白草稿
3. 如需新复合指标，用户可创建指标草稿，并依次完成校验、单股预览、小样本预览与发布
4. 用户可创建 10 到 20 个条件的规则，条件中可混用内建指标、已发布复合指标、标准化财务字段、当前基础股票池内全市场排名与当前基础股票池内申万一级或二级排名
5. 用户保存规则版本并手动运行后，系统按第 19.1 节的性能验收条件满足 5 秒目标
6. 结果页可配置列、多字段排序，只对入选股票给出入选解释
7. 保存结果时标题必填，备注可选
8. 导出 CSV 包含完整溯源信息
9. 结果可加入自选列表

### 20.2 验收流程二：单股研究

前置条件：目标股票存在于股票全集中。

通过标准：

1. 用户可从筛选结果或自选列表进入个股详情页
2. 页面显示代码、名称、拼音、最近收盘价与价格日期
3. 页面展示日 K 线、成交量、均线，并允许 raw 与 qfq 切换、缩放与十字光标
4. 页面展示估值、盈利、成长、安全与股东回报摘要
5. 用户可查看年度默认财务趋势，并切换到季度与 TTM
6. 若指标为 `historical_capable`，则默认展示 5 年，并可切换 1 年、3 年、5 年、10 年、全部
7. 若指标为 `current_only`，系统明确说明其只能用于当前展示
8. 用户可查看关键字段溯源并在浏览器中打开一份已恢复到本地的 PDF
9. 网页中不存在原始报表大表格与多股票对比功能

### 20.3 验收流程三：CLI 与 OpenCode

前置条件：CLI 可执行，OpenCode 已加载对应 skill。

通过标准：

1. 用户可通过 CLI 获取 `schema`、`capabilities` 与 `examples`
2. OpenCode 可发现字段与函数，并用非交互 JSON 创建、校验、预览与发布一个复合指标版本
3. OpenCode 可创建并手动运行一条筛选规则，将结果显式保存、导出并加入自选列表
4. CLI 的所有正式响应均包含 `schema_version`，错误与原因码保持稳定
5. 危险操作首先返回计划对象与 `plan_id`，而不是立即执行
6. 用户在 15 分钟内确认时执行成功，超时确认时被拒绝
7. 用户尝试直接数据库修改、自由脚本执行或直接代码修改时，系统明确拒绝

### 20.4 验收流程四：初始化、更新、修复、归档、备份与恢复

前置条件：全新本地环境或需要修复的现有环境。

通过标准：

1. 用户执行一键启动后，系统先完成第 6.7 节定义的最小可用建设，并展示历史回填状态
2. 下一次启动时，系统只做简单增量检查，识别新交易日、新公告与待重试任务
3. 模拟某来源失败时，系统保留旧值并生成重试列表与缺失列表
4. 模拟 PDF 解析失败时，系统生成可机器处理的失败任务
5. 用户提交受控 JSON 校正模板后，系统完成校验、影响预览与确认发布
6. 用户通过 CLI 创建备份，系统保留最近 3 套全量备份与增量链
7. 用户在归档验证成功后可人工触发本地清理
8. 用户通过 CLI 恢复一套备份，并在浏览器中打开恢复出的 PDF

## 22. 非阻塞风险

以下风险真实存在，但不阻塞 V1 立项与技术规划：

1. 免费数据源存在字段漂移、限流、反爬、临时失效与维护滞后风险
2. `as_reported` 覆盖可能只在部分字段、部分年份、部分行业可得
3. 北交所长尾字段与早期历史可能长期无法与沪深对齐
4. 银行净息差、证券公司净资本、保险偿付能力等行业特有字段可能需要 PDF 辅助，结构化一致性不稳定
5. 当前申万行业归属与历史行业归属是两件不同的事，V1 只承诺当前口径
6. 来源冲突可能长期存在，因此必须依赖溯源保留与人工覆写机制，而不是企图一次性消灭所有冲突

## 23. 已被替代的旧决策

以下想法、草案或旧倾向已被正式替代，不再属于 V1：

1. 从本地单人研究工具扩展为平台化、多人化或公网服务的方向已被放弃
2. 市场总览页已被移出 V1
3. 历史筛选、历史行业排名与回测已移出 V1
4. 平台级覆盖率门禁、每日发布门禁、全量快照放行机制已移出 V1
5. 以外部来源直接提供的估值值作为最终结果的思路已被替代为内部计算优先
6. 全市场、全时期、全字段的完整 `as_reported` 版本链承诺已被移出 V1
7. 北交所与沪深完全等深覆盖的目标已被降级为最小可用覆盖
8. 数据状态页承载写操作的方案已被放弃，全部操作保留在 CLI
9. 自动执行已保存筛选规则的设想已被放弃
10. 自选列表中的备注、目标价、提醒与交易跟踪功能已被移出 V1
11. 网页原始报表大表格与多股对比已被移出 V1
12. 内建 OCR 已被明确排除

## 附录 A：非绑定数据源研究

本附录只服务于后续技术调研，不构成 V1 验收条件，不锁定具体来源、抓取方式、适配器实现或缓存方案。

### A.1 非绑定结论

1. CNINFO 与交易所公告体系应被视为原始披露真值层与溯源层的优先候选
2. AKShare 是广覆盖适配层，不是法定权威披露源
3. BaoStock、腾讯、东方财富、easy-tdx 都可作为候选运行来源，但存在同源风险、维护风险与反爬风险
4. `yfinance` 不应作为 A股主数据源
5. 没有任何单一免费来源能够独立满足本产品全部要求，因此适配器必须可替换，且必须保留原始溯源材料

### A.2 研究说明

- 巨潮资讯网首页明确将自身描述为深交所法定信息披露平台，并提供公告检索、个股 F10 与数据服务入口，适合作为公告真值层与原始 PDF 溯源层的优先候选之一。[1]
- AKShare 官方文档明确提示其采集的数据来自公开源，仅用于学术研究，并说明目标网站变动会导致接口需要持续维护，适合作为广覆盖适配层而不是法定权威源。[2]
- AKShare 股票数据文档显示其 A股行情能力大量建立在东方财富等公开网页接口之上，说明其可作为运行适配层，但不能被误解为单一权威主源。[3]
- AKShare 的 A股历史行情实现直接使用东方财富公共接口并支持 raw、qfq 与 hfq，说明它是运行适配层而不是交易所权威源。[3]
- 申万当前一级与二级行业数据可由申万宏源研究 current API 的现有封装获取，但该能力只支持本文所需的当前口径，不等同于历史成员或历史排名。[4]
- Qlib 的公开 PIT 采集说明明确提示其免费数据可能不完美，且社区还存在 PIT 采集与可用性问题，因此不宜把它当成 V1 的现成官方级 PIT 解决方案。[5][6]
- 免费数据运行风险是现实存在的，例如 AKShare 社区中持续可见东方财富相关接口失效、断连或不可访问问题，因此适配器可替换与原始溯源保留必须是产品约束，而不是实现偏好。[7]
- `yfinance` 官方 README 明确说明其与 Yahoo 无从属关系，数据用于研究与教育场景，且 Yahoo 数据本身意在个人用途；结合 A股覆盖现实，它不应成为本产品的 A股主数据源。[8]

# Value Dashboard 安全优先审计修复设计

## 1. 目标

以 `docs/11_RED_TEAM_AUDIT_V2.md` 为唯一当前审计基线，解除程序层面的数据损坏风险和错误语义，并把缺少外部真值的数据问题明确暴露为缺失、陈旧或待隔离状态。

## 2. 实施边界

### 自动修复

- DQ-01：分红摘要 SQL。
- DQ-02：快照 staging 计算与事务发布。
- DQ-04：适配器别名、备源链和未知配置拒绝。
- DQ-08：pytest 收集零副作用、临时数据库 fixture、遗留脚本退出 pytest 收集面。
- DQ-09：TTM/YoY/QoQ 不再返回伪语义；能正确计算的路径使用构造数据验证，未实现路径显式拒绝。
- DQ-10：raw/qfq 分开判定，非豁免 qfq 缺失不得报告成功。
- DQ-11：未知元数据保留 `NULL`，空值不得覆盖已有值。
- DQ-12：只有 published 且未撤销的唯一覆写可参与计算。
- DQ-13：增加幂等 DuckDB schema 迁移，使新库和旧库一致。
- DQ-14：增加显式事务上下文，危险写入失败自动回滚并记录 retry/missing。

### 非破坏性治理

- DQ-03：不删除现有 BaoStock 壳行；指标选择“最新完整报告期”，新写入增加完整度门禁，状态 API 同时展示最新记录日期和最新完整日期。
- DQ-05：不猜测真实除权日；无法验证的期末占位日期不得作为严格可信分红事件，相关能力返回缺失原因。
- DQ-06：不伪造 lineage；状态 API 暴露孤儿批次、无效哈希和 synthetic summary 风险。
- DQ-07：API 和页面展示财务日期、价格日期、计算日期及陈旧警告。
- DQ-12：不自动删除现有筛选结果、覆写或作业记录；只阻止未发布覆写继续影响计算。

## 3. 数据安全设计

### 正式数据备份

修复前复制 DuckDB 和 SQLite 到 `data/backup/audit_pre_fix_20260720.*`，保存 SHA-256。所有复现测试使用临时库或备份副本。

### 快照发布

1. 从正式 `indicator_snapshot` schema 创建唯一 staging 表。
2. 所有计算结果仅写 staging。
3. 校验行数、主键唯一性、必填列和失败列表。
4. 仅在完整成功时，于单一显式事务中用 staging 内容替换正式表。
5. 任何异常或部分失败均保持正式表逐行不变。
6. staging 在成功或受控失败后清理；进程崩溃留下的旧 staging 在下次运行前清理。

### 测试隔离

pytest 只收集真正的断言式测试；历史 `test_m*.py` 输出脚本不再作为 pytest 模块导入。数据库 fixture 将正式库复制到 `tmp_path` 或初始化空临时库。`pytest --collect-only` 前后正式数据库 SHA-256 必须一致。

## 4. 数据语义设计

- 完整财务报告期必须同时满足资产负债表核心恒等字段与利润表核心字段非空；壳行只算“最新记录”，不能算“最新完整报告”。
- 分红事件只有在日期来源可验证时参与严格日期型指标；占位日期保留原始记录但不提升置信度。
- TTM 使用“最近年报 + 当前累计 - 去年同期累计”；年报自身等于 TTM。无法满足输入条件时返回缺失，不返回年度值冒充 TTM。
- DSL 当前无法在单行快照查询上正确实现历史窗口函数，因此未完成历史执行上下文前，TTM/YoY/QoQ 必须显式拒绝，而不是生成旧值或原值。
- 未知停牌状态为 `NULL`，不能默认为 `False`。

## 5. 验证设计

- 单元测试：分红聚合、TTM 构造数据、适配器配置规范化、完整报告筛选、元数据 UPSERT、覆写发布状态。
- 集成测试：DuckDB 事务回滚、快照失败注入、schema 新建/升级幂等、raw/qfq 写入原子性。
- 收集安全：正式数据库哈希在 `pytest --collect-only` 前后相同。
- 应用验证：代表股票指标计算、CLI 只读命令、FastAPI 状态/详情端点、前端类型检查和构建。

## 6. 完成定义

- 所有可由本地代码和构造数据判定的审计缺陷均有红绿回归证据。
- 正式数据库不因测试或失败重算而改变。
- 现有不可信数据被诚实标识，不再静默参与严格指标。
- 需要外部真值或数据所有者确认的项目明确保留为阻断项，不虚假宣称解除全部 BLOCK。

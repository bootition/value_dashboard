# 价格更新流水线实证与批量持久化报告（2026-08-07）

## 1. 大规模实测回放（正式库、逐步定位）

在正式库上连续多轮实跑价格补全（4693→4213 只剩余缺口），逐轮定位瓶颈：

| 版本 | 实测速率 | 定位 |
|---|---|---|
| 初始（baostock 0.1s、串行、逐值审计） | ~2.4 股/分 | baostock 服务端 ~90s 隐式限流惩罚 |
| +tencent 主源 +并发4 +限速校准 | ~5.2 股/分 | persist 行数大（tencent 忽略 start_date） |
| +tencent start_date 过滤（增量只落缺失行） | 未改善 | **主循环逐股事务成为瓶颈**（fetch 4/s vs done 0.1/s） |
| +移除价格逐值审计（PRD §14 仅关键财务字段） | 未改善 | 同上 |
| **+批量持久化（20 股/事务）+并发8** | **16.9 股/分** | WAL 提交次数减少约 20 倍 |

三个隐藏根因（均被真实运行暴露、非文档可查）：
1. **腾讯 newfqkline 忽略 start_date**：永远返回最近 640 根。适配器现已按 `start_date` 过滤返回行，增量请求只落缺失几天。
2. **价格逐值审计放大**：每股 ~640 行 × 7 数值字段 × 2 表 ≈ 9000 行 source_audit 插入，非 PRD 关键字段所需。价格改为 batch 级溯源。
3. **逐股事务的 WAL 提交开销**：改为每 20 股一个 DuckDB 事务，失败自动回退逐股原子提交（断点续传保持）。

## 2. 大规模限流验证

连续 ~9 分钟、5.5 fetch/s 峰值下，tencent 无任何 >30s 惩罚、无错误（fetch 日志 900+ 次全部成功）——与校准实验（0.2s 间隔无惩罚）一致。baostock 已退居兜底（0.8s 限速）。

## 3. 当前状态与预期

- 剩余缺口约 4213 只，当前 16.9 股/分 → 预计约 4 小时完成全量价格补全；此后日常增量（每日 ~1-3 行/股）将远快于此。
- 断点续传、进度回调、重试列表语义均保持（批量失败自动逐股回退）。
- 验证：后端回归 28/28（批量/续传/适配器）+ Ruff 全绿；观测脚本自含清理不留残留进程。

## 4. 后续候选（未实施）

- 更高并发（16）需观察 tencent 长期风控；
- 首次全量补齐完成后，将日常增量限速进一步放宽。

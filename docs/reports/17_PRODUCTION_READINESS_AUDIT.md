## 2. P0 — 致命问题（验证确认，阻碍正常使用）

### P0-1：PDF 下载必定崩溃（UnboundLocalError） ✅ 已验证

- **文件：** `app/core/pdf/manager.py:100-117`
- **现象：** `write_bytes` 和 `sha256` 被错误地放在 `return` 之后，变成了死代码。正常路径缺少文件写入和哈希计算，导致 `UnboundLocalError: pdf_hash`。
- **影响：** PDF 下载功能 100% 不可用。

### P0-2：估值指标股本计算根本性错误 ✅ 已验证

- **文件：** `app/core/indicators/calculator.py:270-280` 及 `:706`
- **现象：** 用 `paid_in_capital`（实收资本，单位：元）当作总股本（单位：股）。以贵州茅台为例：`paid_in_capital` ≈ 125.6 亿元，实际总股本 ≈ 12.56 亿股，`total_market_cap` 偏差约 10 倍。
- **影响：** PE_TTM、PB_MRQ、PS_TTM、PCF_TTM、总市值、流通市值、分红率 **全部错误**。

### P0-3：SW 行业分类永远失败 ✅ 已验证

- **文件：** `app/core/init.py:222`
- **现象：** 代码查找 `config/sw_industry_cache.csv`，但实际文件是 `config/sw_industry_fallback_result.json`（JSON 格式）。
- **影响：** 所有股票的 `sw_level1`/`sw_level2` 字段保持 NULL，行业分类功能失效。

### P0-4：SQLite 事务连接缺少 busy_timeout ✅ 已验证

- **文件：** `app/core/storage/sqlite_store.py:63-74`
- **现象：** `transaction()` 创建新连接但未设置 `PRAGMA busy_timeout=5000`。
- **影响：** 高并发写入时可能报 "database is locked"。

### P0-5：restore_pdf 路径穿越漏洞 ✅ 已验证

- **文件：** `app/core/pdf/manager.py:251-258`
- **现象：** `stock_code` 和 `filename` 直接拼接路径，无任何校验。
- **影响：** 安全漏洞，可读取/覆盖任意文件。

### P0-6：DuckDB schema 迁移非幂等 ✅ 已验证

- **文件：** `app/core/storage/schema.py:494-495`
- **现象：** `ALTER TABLE ... DROP DEFAULT` 每次启动都执行，某些 DuckDB 版本会抛异常。
- **影响：** 启动时可能崩溃。

### P0-7：confirmed_at 列不存在 ✅ 已验证

- **文件：** `app/cli/protocol.py:215`
- **现象：** `ORDER BY confirmed_at DESC` 引用了 `plans` 表中不存在的列。
- **影响：** 危险操作确认流程完全不可用。

### P1-0（原 P0-8）：模块导入副作用 ✅ 已验证，降级为 P1

## 5. 误报排除

### P1-3（原报）：自选股 INSERT OR REPLACE 丢失时间戳 ❌ 误报

- **验证结论：** `watchlist` 表没有 UNIQUE 约束，`INSERT OR REPLACE` 不会触发冲突替换，而是直接 INSERT 新行。实际问题是重复行，非时间戳丢失。

### P1-4（原报）：SPA fallback 吞掉 API 404 ❌ 误报

- **验证结论：** FastAPI 路由匹配是具体路由优先。API 路径有明确路由定义，会优先匹配。

# 最终筛选界面与自动更新恢复报告（2026-08-05）

## 1. 筛选界面

- 完全替换原有筛选条件表格：采用方正边框、研究底稿式网格，无圆角卡片和阴影。
- AND/OR 改为“同时满足全部条件 / 满足任意一个条件”，条件之间显示“并且 / 或者”；嵌套组沿用同一语法。
- 操作符改为“高于、低于、不低于、位于区间、有数据”等中文判断，保留原规则 JSON 与后端执行契约。
- 新增条件编辑器组件测试，覆盖全部/任一逻辑切换与连接词。

## 2. 状态一致性

- 侧栏原来读取不存在的 `data_quality.ready`，因此永远显示“数据未就绪”；现统一读取 `data_quality.minimum_data_readiness.ready`。
- 筛选页不再把“状态 API 可访问”误写成“数据可筛选”，与侧栏、数据状态页使用同一 ready 判定。
- 数据状态页新增目标交易日及 raw/qfq 完整覆盖数，并显示自动更新最近结果和跳过原因。

## 3. 自动更新根因与修复

正式库曾有死亡 PID 锁和悬挂 `running` 作业；Windows `OpenProcess` 假阳性使死亡 PID 被误判为存活，后续更新全部被跳过。修复包括：

- 用进程退出码 `STILL_ACTIVE` 判断 Windows PID；回收死亡锁时自动结算悬挂增量作业。
- 价格提升到每日流程首阶段，前置检查不再重复抓全市场公告。
- 非停牌股票按各自 raw/qfq 最新日期判断缺口；每只股票价格与溯源原子提交，中断后可继续。
- BaoStock 长任务复用一次会话；TDX 不再接收其不支持的 qfq 请求。
- CSRC 空结果不再触发 `executemany([])`；partial 尝试也按 30 天节流。
- 价格变更只原子增量发布对应股票快照；财务/股本变化仍走全量门禁。
- 上市不足 90 天且免费源尚未形成核心数据的新股只披露、不伪造、不阻断成熟股票研究；股本关系错误仍阻断。

## 4. 正式库处理与复验

- 精确删除测试遗留：`test_group/600519`、`default/002027` 与 `test_rule`；当前自选与保存规则均无测试记录。
- 悬挂作业已通过两段式 `reconcile_jobs` 结算；`running_jobs=0`。
- 自动更新 10 股 smoke：`prices=success 10/10`，约 16 秒，状态落为 `finished/success`。
- 421 只已更新成熟股票的指标快照完成原子增量发布。
- 最终正式状态：`ready=true`、`warning_codes=[]`、最新可得价格日与指标快照价格日均为 `2026-08-05`。
- 覆盖披露：目标交易日 `2026-08-05`，非停牌股票 `5530`，raw/qfq 同步达到目标日 `245`；其余股票仍由后续自动更新追赶。因此不得表述为“全市场价格已完整更新到 08-05”。
- 4 只极新股（`001232`、`301677`、`920038`、`920258`）免费源核心数据未形成，作为披露项延后研究。

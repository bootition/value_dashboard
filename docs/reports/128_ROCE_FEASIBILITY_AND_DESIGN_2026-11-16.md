# ROCE（已动用资本回报率）可行性审查与构建口径设计

> 需求来源：用户提出新增复合指标「已动用资本回报率 ROCE」——
> **ROCE = 当期息税前利润 ÷ 当期平均已动用资本**，
> 其中 **已动用资本 = 净营运资本 + 固定资产净值**，
> 含义是「今年投 100 元资本，一年赚回 20 元」（ROCE = 20%）的企业用钱能力。
>
> 本报告只做两件事：**（1）正式库数据是否支撑按该定义构建；（2）按该定义应该怎么构建**。
> 数据核查全程**只读**（DuckDB `read_only=True`），未写库、未动 schema。
> 唯一代码改动是查证途中发现并修复的 DSL 括号缺陷（§6.2），与本指标落地无关、可独立回滚。
> 复现脚本：`.planning/2026-11-16-roce-metric/`（会话产物，不入库）。

## 2. 定义拆解 → 需要哪些字段

用户的定义可以逐步翻译成库里的列：

| 定义成分 | 数学表达 | 数据库来源 | 字段 | 说明 |
|---|---|---|---|---|
| 息税前利润 EBIT | `利润总额 + 财务费用` | `income_statement` | `total_profit`, `financial_expenses` | 与 `indicator_ext.ebit`（CSMAR FI_T5.F050601B 口径）一致，见 §4.1 |
| 净营运资本 NWC | `流动资产合计 − 流动负债合计` | `balance_sheet` | `total_current_assets`, `total_current_liabilities` | 标准教科书口径，不减现金、不减短期借款 |
| 固定资产净值 FA | `固定资产` | `balance_sheet` | `fixed_assets` | 中国准则资产负债表上的「固定资产」**已是扣除累计折旧后的净额** |
| 已动用资本 CE | `NWC + FA` | 派生 | — | |
| 当期平均 | `(期初 + 期末) / 2` | 派生 | — | 期初 = **去年同期**资产负债表，与现有 `roe`/`roa` 的 P1-24 平均口径同构 |

**核心结论：定义里要的每一个成分都是主链上已有的一等公民列**，不依赖 `raw_data` JSON、不依赖 CSMAR 原始包、不需要新增抓取。

字段中文名先对齐一次（避免口径争议）：

- `total_profit` = **利润总额**（税前、含营业外）
- `financial_expenses` = **财务费用**（= 利息费用 − 利息收入 + 汇兑损益 + 手续费，**净额**）
- `fixed_assets` = **固定资产（净额）**，不含在建工程、不含使用权资产、不含无形资产/商誉

## 4. 五个必须先定的口径问题（每个都有实测依据）

### 4.1 「息税前利润」用哪个口径？

库里三种候选：

| 候选 | 公式 | 最新期覆盖 | 评述 |
|---|---|---|---|
| **① 利润总额 + 财务费用** | `total_profit + financial_expenses` | **6,170 / 6,280 = 98.3%** | CSMAR FI_T5 口径，**项目已有 `indicator_ext.ebit` 用的就是它** |
| ② 净利润 + 所得税 + 财务费用 | `net_profit + income_tax + financial_expenses` | 6,035 = 96.1% | 与 ① 数学等价（利润总额 = 净利润 + 所得税），覆盖更差 |
| ③ 利润总额 + 利息费用 | `total_profit + interest_expense` | 5,714 = **91.0%** | 最接近教科书 EBIT，但覆盖差，且实测 `interest_expense` **存在负值**（美的 −13.18 亿），字段语义不稳定 |

**实测**：① 与 ② 的差异中位数为 **0.00 亿元**（数学上完全等价，只是覆盖不同）；① 与 ③ 的差异中位数虽只有 0.0024 亿，但**相对差异 p90 = 49%、p99 = 438%，3,005 只股票相对差异 > 5%**——因为 `财务费用` 是净额（含利息收入与汇兑），净现金公司的 `财务费用` 为负、`利息费用` 为正。营业利润口径（`营业利润 + 财务费用`）与 ① 的差异中位数仅 0.0019 亿，但**营业利润含投资收益/公允价值变动**，不是「息税前经营利润」。

**裁定：用 ①（利润总额 + 财务费用）。**
理由：(a) 与项目既有 `indicator_ext.ebit` 同一表达式，避免同一概念两套数（D23 同类教训）；(b) 覆盖最高；(c) 净现金公司会被**保守低估** EBIT，方向安全。回退链：`利润总额 + 财务费用` → `利润总额 + COALESCE(财务费用,0)` → `净利润 + 所得税 + 财务费用`。

> ⚠️ 已知偏差（必须披露）：对 1,191 只 `财务费用 < 0` 的净现金公司，本口径 EBIT 略低于教科书 EBIT（按 `利息费用` 加回时更高）。若改成 ②→③，覆盖率会掉 7 个百分点，且 `interest_expense` 的负值样本需要单独清洗，**不建议**。

### 4.2 「当期」是 TTM、累计还是年报？

项目内两套既有做法：`indicator_snapshot` 的 ROE/ROA/ROIC 用 **TTM**；`indicator_ext` 的周转率/杠杆用 **报告期累计（YTD）**。

实测：非年报期，TTM 与 YTD 的 EBIT 差异中位数为**去年同期值的 19.3%**（n = 6,263），即口径选择会让结果系统性差近两成。

**裁定：TTM。** 理由：(a) 与 ROE/ROA/ROIC 完全同族，同页可比；(b) 资产负债表是时点量、利润表是流量，TTM 才是「过去 12 个月」与「(去年同期 + 本期)/2」自洽的配对；(c) 季报累计值直接除以年度平均资本会**系统性低估** Q1/Q2/Q3 的 ROCE（Q1 只有 3 个月利润）。

TTM 求法与现有 `_get_ttm_data` 完全一致：
- 最新期是年报 → `EBIT_TTM = EBIT(本年)`
- 否则 → `EBIT_TTM = EBIT(上年年报) + EBIT(本期累计) − EBIT(去年同期累计)`，三缺一 → NULL（**不外推、不用旧年报顶替**）

### 4.3 分母为负/为 0 怎么办？

实测活跃池 **219 只（3.93%）** 的两期资本占用**至少有一期非正**（另有 96 只金融业根本没有这个分母）。

典型：中国交建 −344.82 亿、伊利股份 −56.30 亿、中国中铁、比亚迪（NWC −828 亿但 FA 2,671 亿，仍为正）。

**裁定：任一期末资本占用 ≤ 0 → 写 NULL，原因码 `INVALID_DENOMINATOR`；不取绝对值、不按 0.0001 兜底、不换宽口径。**
并且要求**两期都 > 0**（不只是平均 > 0）：`CE_t = −50, CE_p = +150 → 平均 +50` 会算出荒谬的大数（实测 000035 中国天楹即此类，原始 ROCE 760%）。

> 这类公司大多是**负营运资本经营模型**（先收钱/压货款），本身是好生意，只是「净营运资本 + 固定资产」这个分母**不描述它占用的资本**。如实缺失比给一个 300% 的排名更有用。

### 4.4 病理值要不要封顶？

加「两期均正」后（活跃池 5,174 只）仍有 **41 只 \|ROCE\| > 100%**、6 只 > 200%、4 只 > 300%、1 只 > 500%、34 只 < −100%。

**裁定：`|ROCE| > 3.0`（300%）→ NULL，原因码 `INVALID_DENOMINATOR`。**
实测该阈值只剔除 **9 只**（0.16%：4 只 > 300% + 5 只 < −300%），是廉价的保险；阈值来自数据——护栏内 p95 = 35.8%、p99 = 84.6%，300% 以上属分母塌缩区而非真实经营回报。

⚠️ 但**300% 以内的极端值依然要读作「资本占用极低」而不是「超级赚钱」**（如招商公路 190%、小商品城 158%）。前端建议对 `ROCE > 100%` 加提示。

### 4.5 金融业怎么办？

金融业活跃 116 只，其中 **96 只**（38 银行 + 36 券商 + 保险等）的资产负债表**没有流动/非流动划分** → `total_current_assets` / `total_current_liabilities` 为 NULL。

**裁定：写 NULL，原因码 `NOT_APPLICABLE`（不是 `SOURCE_EMPTY`）。**
「净营运资本 + 固定资产」对银行/券商本就没有业务含义（存款是流动负债、贷款是非流动资产），缺失语义是正确的。不要为它们发明替代分母。

### 4.6 历史上的 `fixed_assets` 缺口

| 报告期 | `fixed_assets` 覆盖 |
|---|---|
| 2026-09-30 / 2026-06-30 / 2026-03-31 | 100.0% / 100.0% / 99.9% |
| 2025-09-30 / 2025-06-30 | 99.6% / 99.5% |
| **2025-03-31** | **84.4%** |
| 2024-12-31 / 2024-06-30 | 99.9% / 99.2% |
| **2024-09-30 / 2024-03-31** | **84.1% / 84.5%** |
| **2023-09-30 / 2023-03-31** | **84.5% / 83.6%** |

即 **2025-06 之前的 Q1/Q3 报告期系统性缺 15%**（这正是 `reports/119` 记录的「2026Q3 固定资产只剩 1.8%」同一类断供的历史残留）。

影响判定：
- **当期快照（本次目标）不受影响**：最新期 100%，去年同期 2025-09-30 为 99.6%。
- **将来若要做历史序列**，Q1/Q3 会缺 15%；届时**以年报期为锚**构建（年报期覆盖 99.7%+），或先回填历史 Q1/Q3 的固定资产。

### 4.7（附加）点及时性：历史序列不能做无偏回测

`report_metadata.declare_date`（公告日）整体覆盖率只有 **10.1%**（35.7 万行中 3.6 万），**2024–2025 年几乎为 0**（2025 年 5,487 行中只有 7 行）。

**结论：ROCE 可以做「按报告期」的当前值与历史展示，但不能用来做「按公告日」的无前视回测**。若将来要回测，需要先补公告日（CSMAR `DeclareDate` 原始包里有，见 `reports/119` §5）。

## 5. 推荐构建口径（施工规格）

### 5.1 公式（唯一版本）

```
EBIT_TTM  = TTM(利润总额 + 财务费用)                        # 见 §4.1 / §4.2
CE(t)     = 流动资产合计(t) − 流动负债合计(t) + 固定资产净值(t)
AVG_CE    = ( CE(t) + CE(t−12个月) ) / 2                   # 两期都必须 > 0
ROCE      = EBIT_TTM / AVG_CE                              # 存小数比例：0.2034 = 20.34%
```

### 5.2 护栏与 NULL 原因（与 `indicator_null_reason` 的 6 个码一一对应）

| 条件 | 结果 | reason_code |
|---|---|---|

## 6. 今天就能用：DSL 自定义表达式（含本轮修复的括号缺陷）

### 6.1 期末口径 ROCE 可以直接写成 DSL 表达式

```text
(income.total_profit@TTM + income.financial_expenses@TTM) /
(balance.total_current_assets@LATEST - balance.total_current_liabilities@LATEST
 + balance.fixed_assets@LATEST)
```

经 `parse → expand_shorthand → validate → codegen` 后直接在正式库执行（只读实测）：

| 项 | 值 |
|---|---|
| 全市场非空 | **5,393 / 5,575**（96.7%） |
| 600519 贵州茅台 | 44.8% |
| 000333 美的集团 | 46.2% |
| 601088 中国神华 | 28.5% |
| 000858 五粮液 | 14.1% |
| 600858 银座股份 | 151.5% |

与 §6 的平均口径相比（茅台 46.2%、美的 58.1%）方向一致、量级吻合。**能算，但没有**：平均分母（DSL 未暴露「去年同期值」）、两条护栏、金融业区分。这些只有内置指标能给。

### 6.2 查证时发现的 P1 缺陷：DSL 解析器不支持括号（已修复）

**症状**（`app/core/dsl/parser.py`，自仓库基线起即存在）：

| 表达式 | 修复前 | 修复后 |
|---|---|---|
| `(1)`、`((1))` | 返回 lark `ParseTree`（不是 AST） | `Literal(1.0)` |
| `a / (b - c + d)`（**ROCE 形态**） | `AttributeError: 'Tree' object has no attribute 'unit'` → HTTP 500 | 正常编译 |
| `2 * (x + 1)` | 同上 | 正常编译 |
| `(a + b) > 100` | 校验器在 `left.unit` 上崩 | 正常 |
| 绕过校验直接 codegen | 编译成**字面量 `NULL`** → 规则永远命中 0 只、不报错 | `UnsupportedPeriodFunctionError` |

**根因**：`_get_parser()` 用 `keep_all_tokens=True`，而 grammar 的括号是 `primary` 的未命名分支 `"(" expr ")"` —— 该分支解析树带 `(`、`)` 两个 Token 共 3 个孩子，于是 `?primary` 的"单孩子内联"失效，`Tree('primary')` 原样漏到上层，被 `multiplicative()` / `Validator._check_dimensions()` 当 AST 用。

**修复**（3 处 + 12 条用例）：

1. `app/core/dsl/parser.py`：新增 `DSLTransformer.primary()`，丢弃括号 Token、把内部表达式原样返回（括号只影响优先级，不改变语义）；
2. `app/core/dsl/codegen.py`：删掉 `_gen_expr` 的兜底 `return "NULL"`，改为抛 `UnsupportedPeriodFunctionError` —— 编译不出来必须**显式失败**，不能再变成"永远筛 0 只"；
3. `tests/regression/test_dsl_parenthesis.py`（新，12 用例）：括号返回真 AST、四则/比较/嵌套优先级、括号不污染量纲、ROCE 形态能编译出真实 SQL、兜底不许产生 NULL、校验器接受括号表达式；
4. `tests/regression/test_screening_config_limits.py`：3 处 `assert parse(...) is not None` 改为 `assert isinstance(..., ASTNode)` —— 旧断言在缺陷下**一直是绿的**（`Tree` 不是 `None`），这正是缺陷能长期存活的原因。

**验证**：DSL / 筛选 / 期间语义相关 **180 个既有用例全绿**（`test_dsl_*`、`test_screening_*`、`test_p0_3_p0_4_regressions`、`test_period_semantics`、`test_wheel_contents` 等），`ruff check` 通过。

> ⚠️ 正式 S1 门禁（`scripts/s1-pytest.ps1`）**本轮未跑**：它要求 8765 端口无服务，而用户仪表盘正在运行。上面 180 个用例是以隔离 profile（`VD_ENV=test` + 独立 `VD_TEST_RUN_ROOT` + wrapper 语义的基线指纹）直接跑 pytest 得到的，未触碰正式库。**服务停掉后需要补跑一次官方 S1**。

## 8. 已知局限（必须对用户披露，不打算修掉）

| # | 局限 | 影响 | 处置 |
|---|---|---|---|
| L1 | `净营运资本 + 固定资产净值` 对**负营运资本**与**轻资产**公司分母塌缩 | 219 只 NULL、9 只被护栏剔除；护栏内的极端值仍需人工判断 | 如实披露；必要时未来补一列宽口径（总资产 − 流动负债）**另行立项**，不并列暴露两个近似指标（参考 `dividend_yield` vs `ttm_dividend_yield` 的废弃教训） |

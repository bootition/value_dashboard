# 返工与事故复盘（最近一个月）

> **一句话结论**：最近一个月 46 次提交里 23 次是 `fix`，其中 60% 的修复在 96 小时内
> 又改到上一份提交改过的同一批文件。返工不是"某几次手滑"，而是 **7 类固定生产机制**
> 在稳定地制造同类缺陷；真正能降本的不是更努力地修，而是把其中可机械判定的 4 类
> 变成会失败的门禁、把 2 类变成必须走的流程清单、把 1 类（口径设计）变成 Skill。

---

## 1. 结论（TL;DR）

1. **量**：窗口内 46 commit / 52,825 insertions / 3,051 deletions；`fix` 占 50%
   （23 次），`docs` 12 次，`feat` 6 次，`perf` 3 次，`chore` 2 次。
   测试代码新增 18,308 行（占新增 35%），说明"补测试"已经不是稀缺动作——
   **稀缺的是"让测试在写错的当天就红"**。
2. **返工**：25 次 `fix`+`chore` 中 **15 次（60%）在 96 小时内改到与上一份提交
   ≥40% 相同的文件**；19 份报告里 **5 份（26%）在自己发布的同一天或次日被
   `superseded`**。ROCE 一个指标 **40 小时内返工四次**（`128→129→130→132`），
   累计 4,322 行改动；分红除权日 PDF 方案 **26 小时建成又被整体删除**
   （1,769 行代码/测试 + 353 行报告）。
3. **不是"人不行"**：9 个显式标注 P0 的事故 + 1 个环境级事故里，没有一个是
   "不知道怎么写代码"；全部是**同一件事在两处被实现**、**状态不是从事实推出来的**、
   **派生列没有重建/保全契约**、**除法与单位没有外部校准**、**时区靠自觉**、
   **单点故障被放大成全局拒绝**、**守卫写了但从未生效**。
4. **已沉淀**（本次交付，全部版本化且进门禁）：
   * 规则：`AGENTS.md` §6「反返工硬规则」（7 条，每条绑定一个自动化或清单）
   * 自动化：`scripts/check_rework_guards.py`（RG1–RG4 静态门禁）
     + `calculator._derived_columns_guard()`（发布期不变量：派生列不许被清空）
     + `tests/regression/test_rework_guards.py` / `test_snapshot_derived_columns.py`
   * Skill：`docs/skills/composite-indicator/SKILL.md`（复合指标 10 步清单）
5. **本次复盘当天就抓到 3 个存量缺陷**（这也是唯一可信的验收方式——
   门禁必须能抓到东西，否则就是 `reports/125` 那种"写了但从未生效"的守卫）：
   * 增量发布路径仍在清空 ROCE 六列（`reports/131 §9` 的补丁只补了整表路径）；
   * 前端把 `cash_content_of_revenue`（≈1.0 的倍数）登记成小数比例 → 100 倍误差；
   * `balance.advance_from_customers_ratio` 后端登记为倍数、前端缺登记 → 退回百分数。

## 4. 共同根因（7 类，按"能被机械拦截的确定性"排序）

> 每条都是"机制 → 证据 → 代价 → 反事实"。反事实是这次真正要买的东西：
> **如果当时有这条控制，会在哪一步停下来。**

### R1 单一事实在多处实现（SSOT 违反）

**机制**：同一件事在两个以上地方各写一遍。两处都会"看起来对"，只有在特定输入下
才分叉；分叉时不报错，只给出两个都自洽的答案。

| 证据 | 后果 |
|---|---|
| `missing_count` 三处口径：日志 11,823 / 网页 162 | 运维照着错的数排障（`117`） |
| 股本缺口两份 SQL：门禁报 5 只、readiness 报 26 只 | 同一状态两个相反结论，`/api/ready` 假红（`117`/`118` P1-3） |
| **总市值 3 套算法** | 185 只差 >1%，最差 **−90%**（`126`） |
| "数据不可信"一个判定、两个出口 | 详情页全变空、筛选页照常出排名（`126`） |
| UTC+8 时区 4 处私有实现（其中一处退化成 `date.today()`） | 两次时区事故（R5） |
| 单位注册表后端 `field_units.py` / 前端 `screening-format.ts` 两份 | 复盘当天抓出 2 处口径矛盾（100 倍误差风险） |

**代价**：`126` 一个提交改了 39 个文件才把"市值单一实现"收口（新建 `market_cap.py` 393 行）。

**反事实**：如果当时有 RG3/RG1 这种"跨文件一致性门禁"，`cash_content_of_revenue`
在写下的当天就会红，而不是等到有人肉眼看出来。

### R2 状态与证据不是从事实推出来的（假绿 / 假成功 / 假签名）

**机制**：状态字段由"最后一个写它的人"决定，而不是由可观测事实派生。表现是
**系统说自己成功，而用户看到的是错的**。

| 证据 | 后果 |
|---|---|
| `{**后一个子步骤, "full_recompute": 前一个}` 让 success 覆盖 rejected；同时把全表 `calculated_at` 刷成当天 | 对外 `success`、快照实际 14 天陈旧（`117` P0-2） |
| `/api/ready` 返回 13 小时前的缓存 `ready:true`，同秒 `/api/health` 503 | **"同一类缺陷换了个入口"**（`118` P0-A，作者自述） |
| 价格步骤 `success` 但 qfq 滞后（`failed==0`） | 详情页指标停在旧值（`118` §7-5） |
| 攒批日志写"批量写入"，实测 **90.9% 的批次 N=1** | **验收证据本身失真**（`118` P1-1） |
| `117` §5.1 写"1,255 只全历史重拉 15.7 min"，核对日志实为 10 只 | 报告结论方向对、归因错（`118` §5 主动更正） |
| `125` 的"启动清扫"守卫从未生效（哨兵精确匹配恒假 + `catch` 吞异常） | 守卫空转 24 小时无人知（`127`） |

**代价**：14 天里所有指标 `null`、筛选 409；排查靠人读 110 分钟日志。

**反事实**：状态合并只有 `merge_step_status()` 一个出口（RG2）+ 日志里必须出现
**真实读数**（`write_batch_sizes`）而不是"批量"二字。这两条都已固化。

### R3 派生域 / 派生列没有重建与保全契约

**机制**：`indicator_snapshot` 的发布是 `DELETE + INSERT`。凡**不由计算器 staging
产出**的列，插入时不会被写 → 静默 NULL。这不是某一处 bug，而是一条**稳定的生产线**。

| 证据 | 后果 |
|---|---|
| ROCE 六列由 `roce_history` 聚合，不在 staging 里 | 每次快照重发把 5,575 行 ROCE 清成 NULL（`131` K5） |
| `indicator_ext` 冻结在 2026-06-30 | 55 项扩展筛选指标全体失效（`119` P0） |
| `capital_history` 域冻结（D28） | 同型 |
| `tech_recompute_pending` / `qfq_refetch_pending` 两个"名单式补丁" | 说明缺的是**通用机制**，不是某个名单 |

**代价**：`119` 的 P0 让 55 个筛选条件"能选但筛不出结果"，用户无法分辨是
"没有符合条件的公司"还是"数据坏了"。

**反事实**：`derived_snapshot_domains()` 注册表 + **保全 / 重建 / 校验**三件套。
本次上线当天就照出**增量发布路径仍在清空 ROCE**（`131 §9` 只补了整表路径）——
这条控制的价值当场兑现。

### R4 比率与单位的"分母风险"（除法不报错，只放大）

**机制**：比率类指标的风险不在分子，全在分母。分母被系统性改小 → 结果放大十倍百倍，
**而且看起来很有说服力**。单位换算错 100 倍同理，且显示层与筛选层各自错一半。

| 证据 | 后果 |
|---|---|
| ROCE K1：`net fixed assets` 直译成 PPE 列 | 中油 119%、219 只分母为负、区间 ±10⁴%（`128`） |
| ROCE K2：机械执行"剔除超额现金" | 同花顺 444%、重庆啤酒分母为负（`129`） |
| ROCE K3：`roe if abs(roe) <= 1.0 else None` 护栏掩盖 | **48 只真实 ROE > 100% 被静默写成空值**（用户原话："如果是对的，为什么要剔除"） |
| ROCE K8：没有先用外部标杆校验量级 | 前两版飞出 ±8,000%/444%/1,632%，书里标杆 16%/22%/42% 就摆在那里 |
| 科创板成交量 ×100（`scripts/repair_star_volume_x100.py`） | 指标与筛选同时失真 |
| `dividend_yield` 量纲、`cash_content_of_revenue` 前后端口径矛盾 | 显示 100 倍 / 筛选条件差 100 倍 |

**代价**：ROCE 四次返工 4,322 行；`dividend_yield` 直接进 `DEPRECATED_COLUMNS`。

**反事实**：`docs/skills/composite-indicator/SKILL.md` 的 10 步清单——第 3 步验会计
恒等式、第 4 步**必做外部标杆校验**、第 5 步分母 ≤ 0 必须标 `status` 而不是截断/置空、
第 10 步必须同时给中位/近端/最新。这四步任意一步在场，`128` 都活不过第一个小时。

### R5 时区与交易日边界靠自觉

| 证据 | 后果 |
|---|---|
| `32a2e9d` 日节流标记按 UTC 归零 | 北京时间 00:00–08:00 重跑全量 universe（约 104 s/次） |
| `d7bf840` 详情页数据年龄 UTC/CN 相减 | 刚发布的快照显示 `snapshot_age_days = -1` |
| `118` §3 P2 `price_age_days` **又犯了同一条** | 修一次不够：因为没有单源 |
| `index_valuation_adapter._cn_today()` = `date.today()` | 跟机器时区走，跨机器/跨时区不可复现 |

**反事实**：RG1 + `cn_today()`。本次把 4 处私有实现收敛成 1 处、并修掉 4 处
`datetime.now(UTC).date()` 冒充"今天"的写法，之后由静态门禁永久拦截。

### R6 全局 fail-closed 与故障放大

**机制**：把"数据可能有问题"直接升级成"全站不可用"，或者把单点异常放大成系统性
故障。项目里反复出现同一种形状：**一票否决**。

| 证据 | 后果 |
|---|---|
| 26 只新股股本缺失中 5 只越过 90 天豁免线 | 全市场 5,580 只快照发布被拒（`117` P0-1） |
| `minimum_data_not_ready` 同样是"任一缺口 → 整批不发布" | 同上 |
| 熔断桶 key 只有 adapter 名（无 `data_type`），"有错且无数据"就计数 | 3 个源同时熔断 300s；601123/603435 **零尝试**被记失败并推向 `retry_exhausted` → 永久 `missing`（`117` P0-4） |
| 空适配器链被归类为 `source_unsupported` | 环境问题伪装成"该票没数据"，永久不重试（`118` P1-5） |
| 除权窗口取全市场 `min()` | 一只 qfq 陈旧股把全体拖进全历史重拉：**143.5 min / 38.83 只每分**（`117` P0-3） |

**反事实**：分级门禁（`max(50,1%)` + 占比判据 1/3）、错误分类 `error_kind`、
熔断桶 `(adapter, data_type)`、窗口按股票。已落地，且 `118` 复审把阈值判据
补齐成"小库也不能把 100% 股票隔离光"。

### R7 环境/资源泄漏与不可观测

| 证据 | 后果 |
|---|---|
| S1 包装器只在 `pytestExit == 0` 时清临时目录 | C 盘 **102 GB**、40+ 目录、单轮 **505 个**连锁 `FileNotFoundError` |
| 启动清扫用本轮哨兵校验上一轮目录（精确相等恒假） | 守卫静默空转（`127`） |
| `backup.restore()` 7 个错误分支直接 `return` | `vd-restore-*` 解压目录永久留守 |
| 更新子进程崩溃后 `current_stage`/`job_logs` 永久 `running` | 调度停摆，需重启才能继续（`116`） |
| 更新子进程无 INFO 日志 | "结束更新不可观测"（`8594664`） |

**反事实**：`finally` 无条件清理 + 启动清扫 + 结构化日志 + 心跳看门狗。
这一类已基本收口（`125/127`），本次不再重复造轮子，只在 AGENTS.md 里保留硬约束。

## 5. 为什么同一类问题会反复出现（元分析）

四层结构性原因，比单条根因更值得记住：

1. **修的是出口，不是机制**。`117` 修了 4 个 P0 的**出口表现**，但"状态覆盖"、
   "单点拖全局"、"派生列无契约"这三条机制仍然活着，于是 `118/124/126/131` 各炸一次。
   → 判据：一个修复如果没有改变"下一次同类事故的生成条件"，它就是延期付款。
2. **结论停在散文里**。`131 §10` 已经写出 8 个坑 + 10 步清单——**写得很好，但仍然
   只是一份文档**。文档不会在下次写错时喊停。
   → 本次把其中 3 条能机械判定的变成脚本（RG1/RG3/RG4），其余进 Skill 清单。
3. **守卫没有自证**。`125` 的"启动清扫"、`117` 的"批量写入"、`117 §5.1` 的
   "1,255 只全量重拉"都是**看起来存在、实际不成立**。
   → 新门禁强制带"能抓到东西"的反向用例（`test_rework_guards.py` §2、
   `test_snapshot_derived_columns.py` 第 3 条）。
4. **一次性脚本承载了本该常驻的能力**。`119` 数出 6 条链是"一次性脚本/CLI"，
   不在自动更新主流程里——所以它们会安静地腐烂。

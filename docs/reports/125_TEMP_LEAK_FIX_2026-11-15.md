# S1 测试包装器泄漏临时目录，占满 C 盘（P0 环境事故）与修复

## 1. 结论（TL;DR）

1. **事故**：`scripts/s1-pytest.ps1` 只在**全部测试通过**时删除运行根目录 `%TEMP%\vd-s1-<guid>`，任何失败 / 中断 / `delta` 分支都会把它永久留在 C 盘。每个测试还会在根目录下各复制一份 10–30MB 的 `valuedashboard.duckdb` 快照，单轮 1,500 个用例可达 **20GB+**。现场累积 **40+ 个目录、102GB**，C 盘被占满后**所有测试连锁报错**（实测一轮出现 **505 个 `FileNotFoundError: ...\vd-s1-<guid>\pytest-tmp`**，因为根目录在运行中被清掉/被占满）。
2. **修复**：包装器改为 **`finally` 里无条件清理**（新增 `-KeepRunRoot` 供排障），并在**启动时清扫 24 小时前的残留**——硬杀/断电/蓝屏也不会累积。
   > **2026-11-16 更正**：本条的"启动时清扫"当时**实际从未生效**（用本轮新生成的
   > `$ownershipSentinel` 去校验上一轮目录，精确相等永不成立，异常被 `catch` 吞掉）。
   > 因此"硬杀/断电也不会累积"在 reports/125 阶段**不成立**；已在 `reports/127` 修复并
   > 实证。`finally` 那道保险自始有效，不受影响。
3. **配套**：新增 `scripts/cleanup_leaked_temp.ps1`（默认 dry-run，`-Execute` 才删），用于清理历史泄漏，只匹配 `vd-s1-*` / `vd-t1-*` / `vd-t2-*` / `tmp.*` 且默认只删 30 分钟前的目录（避免误删正在跑的那一轮）。
4. **顺带修掉同类泄漏**：`app/core/backup/manager.py::restore()` 的 7 个错误返回分支原先都直接 `return`，`vd-restore-*` 解压目录永久留在磁盘；已逐分支清理。

## 2. 事故链（为什么是"环境级"问题）

| 环节 | 事实 |
|---|---|
| 触发 | `s1-pytest.ps1` 第 36 行 `$runRoot = Join-Path ([System.IO.Path]::GetTempPath()) "vd-s1-$runId"` |
| 放大 | 第 366 行把 `--basetemp` 指到该目录；每个用例都会在其中创建独立子目录，并**各拷一份完整库快照**（10–30MB） |
| 泄漏 | 第 474–482 行只在 `$pytestExit -eq 0`（且非 PolicyOnly）时 `Remove-Item`；`delta`(99) / `after` 捕获失败(98) / 中断 / 失败一律跳过删除 |
| 兜底失效 | `finally`（第 541 行）只恢复环境变量，**不清理目录** |
| 后果 | 目录累积 → C 盘满 → 后续任何写盘操作失败 → 测试连锁 `FileNotFoundError` / `IOException`，形成"越跑越坏"的正反馈 |

## 3. 修复

### 3.1 `scripts/s1-pytest.ps1`
```powershell
# ① 新增开关（排障用）
[switch]$KeepRunRoot

# ② 开跑前清扫 24h 前的残留
Remove-StaleS1RunRoots -TempRoot ([System.IO.Path]::GetTempPath()) -MaxAgeHours 24

# ③ finally 里无条件清理（保留安全校验，避免误删非本脚本创建的目录）
finally {
    if (-not $KeepRunRoot -and (Test-Path -LiteralPath $runRoot)) {
        Assert-SafeRunTreeForCleanup -Path $runRoot -SentinelValue $ownershipSentinel
        Remove-Item -LiteralPath $runRoot -Recurse -Force -ErrorAction Stop
    }
    ...
}
```
- 清理前仍走 `Assert-SafeRunTreeForCleanup`（校验路径在 TEMP 下、且带本轮 `ownershipSentinel`），**不会误删别的目录**；
- 清理失败会往 stderr 打印**确切的残留路径**，不再静默；
- `-KeepRunRoot` 保留目录并打印路径，供排障。

### 3.2 `scripts/cleanup_leaked_temp.ps1`（新增，一次性清理历史泄漏）
- 默认 **dry-run**：列出匹配目录的 GB / 最后写入时间 / 全路径，并给合计；
- `-Execute` 才删除；`-OlderThanMinutes`（默认 30）避免删到正在跑的那一轮；
- 只匹配目录名 `vd-s1-*` / `vd-t1-*` / `vd-t2-*` / `tmp.*`。

### 3.3 `app/core/backup/manager.py::restore()`
- 7 个错误返回分支（成员过多 / 成员过大 / 总解压过大 / 压缩比异常 / 路径穿越 / ZIP 非法 / 缺 manifest）原先都直接返回，`vd-restore-*` 留在磁盘；
- 已在每个分支前插入 `shutil.rmtree(extract_dir, ignore_errors=True)`。

## 6. 运维纪律（新增）

1. **任何**测试包装器，临时目录必须在 `try/finally` 里清理，不允许以"退出码 == 0"为前提；
2. 磁盘相关的排障入口：`pwsh -NoProfile -File scripts/cleanup_leaked_temp.ps1`（先 dry-run 看体积）；
3. `-KeepRunRoot` 只在排障时使用，用完必须手动删（脚本会打印路径）；
4. 若再次出现"C 盘莫名减少几十 GB"，先查 `%TEMP%\vd-s1-*` 与 `%TEMP%\vd-restore-*`。

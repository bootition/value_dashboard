# 用户启用指南与 UI 分层审查报告（基础可用性 vs 高分美化，2026-08-03）

> 对 `reports/41` 的用户视角审查进一步分层，回答两个问题：
> 1. 是否需要为用户写操作指南？**需要。**
> 2. 是否需要美化 UI？**需要，但必须排在基础可用性闭环之后。**
>
> 本报告不改变 `reports/40` 的正式启用 **PASS**：当前产品可供其 PRD 定义的
> 单用户、本地 Windows、接受 CLI 的目标用户使用。它定义从「可启用」到
> 「普通用户不需要猜测如何操作」以及「有专业产品感」的后续边界。

## 1. 三层标准，不能混为一谈

| 层级 | 定义 | 是否影响当前 PASS | 目标 |
|---|---|---|---|
| L0 基础可用性 | 用户能理解入口、状态、下一步和失败恢复；关键数值单位一致；不误删/不误导 | 对当前目标用户不阻断；对交付给非开发者前应完成 | 能独立完成首次筛选、保存、导出、看数据日期 |
| L1 专业可用性 | 信息密度、响应式、错误文案、表格/图表可读性、键盘可达性达到长期日用标准 | 不阻断 | 用户高频研究不疲劳、不需要反复查文档 |
| L2 高分美化 | 统一视觉系统、品牌气质、精致动效、深色主题、数据叙事与视觉记忆点 | 不阻断 | 由“工具界面”升级为“专业研究工作台” |

**原则：**L0 解决“能不能正确使用”，L1 解决“是否省力可靠”，L2 才解决“是否漂亮、是否有产品感”。
先做 L0，再做 L1；L2 不应掩盖 L0 的缺失。

## 2. 操作指南：属于 L0，建议优先补齐

PRD 的目标用户接受本地部署与 CLI（`docs/decisions/01_PRODUCT_REQUIREMENTS_V1.md` §2.2），
不代表用户应自行推断规则保存、数据日期、strict/approximate、自动更新、备份恢复的
语义。当前 UI 虽能完成操作，但缺少一份从用户目标出发的路径说明；`docs/runbooks/`
目前只有证据保全手册。

### G1 必须提供的“首次使用与日常操作指南”（L0 / P1 UX）

建议新增 `docs/runbooks/user-first-use.md`，README 只放 5 分钟摘要并链接该手册。

| 章节 | 用户要回答的问题 | 验收方式 |
|---|---|---|
| 1. 启动与停止 | 用哪个入口启动？浏览器打不开怎么办？ | 用户按步骤启动 `start.bat`，能打开 localhost |
| 2. 先看数据状态 | 数据是否可研究？价格/财报分别截至哪天？更新中能否使用？ | 用户能在数据状态页读出日期、warning、retry，并知道刷新/CLI 控制入口 |
| 3. 第一次筛选 | 为什么必须先保存规则？如何设置基础池、条件、排序？ | 用户从空白界面在 5 分钟内保存规则并运行一次筛选 |
| 4. 可信度与截断 | strict/approximate/null 是什么？为何有 `_truncated`？ | 用户知道何时不要保存/导出，能解释“仅展示前 5000 条” |
| 5. 保存、导出、自选 | 保存、CSV、加入自选的先后关系是什么？ | 用户能保存、导出、从自选进入个股详情 |
| 6. 个股研究 | raw/qfq、年度/季度/TTM、价格日期和溯源如何阅读？ | 用户能指出一项价格日期与财务报告期 |
| 7. 日常维护 | 自动更新如何查看/暂停/重试？ | 用户能在数据状态页找到 CLI 命令，并执行 `vd data auto-update status` |
| 8. 备份与恢复 | 何时备份？如何恢复？恢复风险是什么？ | 用户知道恢复覆盖现库，先创建备份并按 runbook 操作 |
| 9. 已知边界 | 免费源缺口、920305、金融字段、非投资建议 | 用户知道哪些 NULL/缺口不是零值 |

**L0 验收标准：**一名不参与开发、但符合 PRD“接受本地部署与 CLI”的用户，借助手册
在 10 分钟内完成“启动 → 确认数据日期 → 新建并运行规则 → 保存 → 导出”；遇到
`warning`/`_truncated` 时能说出下一步，不需阅读源码或询问开发者。

## 5. L2 高分美化：应该做，但排在 L0/L1 后

当前界面功能完整但视觉上仍接近“Naive UI 默认组件 + Vite 模板样式”，尚未形成
投资研究工作台的专业感。

| # | 高分操作 | 现状证据 | 建议方向 |
|---|---|---|---|
| V1 | 清理模板残留，建立视觉令牌 | `style.css:18-20,159-169`：18px 全局字体、`color-scheme: light dark`、1126px 固定居中、`text-align:center`，且 `.hero/#center/#next-steps` 等死代码 | 以研究工作台为主题重建 CSS tokens：背景、层级、分割线、风险色、数字字体；删除 Vite 样板 |
| V2 | 统一主题系统 | `App.vue:30` 默认 light `NConfigProvider`，CSS 却声称 dark | 选择“仅亮色”并移除 dark 声明，或完整接入 Naive darkTheme + Windows 偏好/手动开关；不可半接入 |
| V3 | 信息层级与密度 | 16px 间距堆叠卡片、全页面等权 | 筛选页以“规则→运行→结果”为主线；数据状态分为“可研究吗/更新中/详情”；降低无关卡片权重 |
| V4 | 数据研究视觉语言 | 当前数值多为普通文本，趋势 SVG 基础线图 | 统一涨跌/风险/可信度色语义；数字用 tabular-nums；图表增加基准线、tooltip、数据日期徽标 |
| V5 | 微交互与完成反馈 | 多为 toast | 保存/导出/加入自选后提供结果链接、可撤销、下载文件名预览；只使用 opacity/transform，尊重 reduced-motion |
| V6 | 品牌与可信度表达 | 标题为 Value Dashboard，缺少研究定位 | 头部加入“本地 A 股研究”副标题、数据日期/更新状态小徽标；不做花哨大屏或市场噪音 |

### 美化验收标准（避免“AI 样板感”）

- 首页（筛选）3 秒可回答：**正在用什么数据、现在能做什么、下一步点哪里**。
- 风险/不可信/截断状态使用一致、可区分且不只靠颜色。
- 表格和图表优先服务比较与决策，不为装饰牺牲密度。
- 亮/暗任一主题必须完整一致；若不做暗色，明确只支持亮色。
- 视觉变化不改写 PRD 的四页范围，也不引入市场总览、资讯流或交易功能。

## 6. 推荐迭代顺序

1. **迭代 A（L0，必须）**：G1 操作指南 + L0-1 至 L0-7。
2. **迭代 B（L1）**：L1-1 至 L1-7，优先响应式、趋势图、数据状态刷新。
3. **迭代 C（L2）**：V1/V2 先定视觉系统与主题，再完成 V3-V6；不要先堆颜色和动效。
4. 与并行运维项一同完成：O1 性能仪式、O2 运维 runbook、O4 加密口径。

## 7. 最终判断

- **当前状态：PASS，能立即使用。** 该结论来自 `reports/40`（last-reviewed: 2026-08-03）。
- **若目标是交付给首次接触该项目的个人用户：应先完成 L0 和 G1，再交付。**
- **若目标是打造高评价专业产品：在 L0/L1 完成后，UI 美化（L2）非常值得投入。**
  美化不是“换颜色”，而是把数据可信度、研究流程、数字比较和长期日用效率变成可感知的产品能力。

# 个股业务概览数据可行性评估

## 1. 结论

精简业务概览可纳入后续个股详情页重构。现有系统没有公司主营、业务标签或主营构成数据，必须作为独立低频数据域新建；不得将其误作三大财报的实时字段或让其失败阻断股票筛选与 readiness。

首期主源建议为东财 F10 的公开结构化公司资料和经营分析接口。其免费、无需登录且在本次探测中可用，足以支持一句话主营、经营范围、行业，以及按产品、行业、地区的最近报告期主营构成。来源应标为 `approximate`，并显示报告期、来源和抓取时间。

## 2. 已核查现状

- 现有 `DataType` 不含 `company_profile` 或 `business_breakdown`：`app/core/adapters/base.py`。
- 现有 DuckDB `stock_meta` 仅含 CSRC 行业等股票元数据，无主营文本或业务构成表：`app/core/storage/schema.py`。
- 个股详情 API 无业务概览契约：`app/web/api/stock_detail.py`。
- 项目已依赖 AKShare，且已使用东财 F10 财务数据主机；当前已知封禁只涉及东财 `push2/push2his` 行情主机，不涉及 F10 主机：`docs/reports/61_SOURCE_STATUS_PROBE_AND_EASTMONEY_BAN_2026-08-08.md`（last-reviewed: 2026-08-08）。

## 3. 来源探测与分级

| 分级 | 来源 | 可用字段与限制 | 产品裁决 |
|---|---|---|---|
| 首期主源 | 东财 F10 `CompanySurvey/PageAjax` | 公司简介、经营范围、CSRC 行业、员工数等；本次无 token 返回 200 | 采用；公司简介只作事实概览，标 `approximate` |
| 首期主源 | 东财 F10 `BusinessAnalysis/PageAjax` | 按行业、产品、地区的主营收入、成本、利润、占比和毛利率；通常只随半年报/年报更新 | 采用；必须显示最近主营构成报告期，不得标作最新季度 |
| 抽样核验候选 | 巨潮 `p_sysapi1090` | 主营业务、经营范围、机构简介等；请求依赖 `Accept-Enckey` 动态签名 | 不作为全市场自动主源；可用于少量样本核验 |
| 缺失回退候选 | 同花顺主营介绍页 | 一句话主营、产品类型/名称、经营范围；HTML 解析、反爬和页面结构风险高 | 仅在主源缺失时尽力使用；不作覆盖承诺 |
| 不采用 | Tushare | 主营构成/公司资料接口需要高积分 | 违反 PRD 完全免费约束 |
| 不采用 | 沪深交易所公司资料网页、新浪页面 | 本次未发现稳定的免费结构化全市场接口 | 不作为运行依赖 |

## 4. 产品范围与数据语义

已确认采用以下范围，待个股详情整体信息架构完成后统一写入 PRD：

1. 首屏身份区之后增加精简业务概览：一句话主营、行业、最近主营构成报告期、按产品/行业/地区的前列标签。
2. “经营与成长”研究章节展示最近报告期的主营构成明细和可得历史趋势。
3. 不自动推断护城河、竞争优势、行业前景或投资结论。
4. 不建设完整 F10、资讯流、管理层档案、客户供应商关系或行业政策终端。
5. 数据低频更新，建议财报期后触发或按月检查，限速不高于 2 req/s；失败保留旧值、记录独立缺失/重试，不阻断日常价格更新、筛选和 readiness。
6. 每项数据保留来源、报告期、抓取时间、原始响应哈希和置信度；必要时允许既有人工覆写流程处理明显错误或缺失。

## 5. 实施前验证

- 使用隔离 profile 对不少于 20 只沪深北股票探测覆盖、字段完整性、报告期和文本质量。
- 抽样与巨潮公开资料人工核验，不将核验结果扩展为全市场自动依赖。
- 为新表、解析、低频更新、保留旧值、A 股 readiness 隔离和详情 API 添加 S1 回归。
- 在正式库有界运行前，检查东财 F10 主机仍可用，并遵循现有源冷却/限流纪律。

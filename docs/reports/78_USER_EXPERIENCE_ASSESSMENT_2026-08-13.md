## 一、实测事实

### 1. 启动耗时（2026-08-13 实测，正式库 10GB）

| 阶段 | 实测 |
|---|---|
| 双击 start.bat → 浏览器可打开页面 | **8~12 秒** |
| 前端需重建（首次/改过代码） | 额外 10~20s，仅一次 |
| 健康检查通过（/api/health 200） | 约 8~10s 后 |
| 当天数据无缺口 | 后台核对 3~5 分钟（不影响看页面） |
| 错过 1 个交易日 | 后台价格更新约 70 分钟（79.5 只/分 × 5,537 只；期间筛选 409） |

启动链路（`app/web/main.py run_server`）：路径校验 → 恢复待回滚检查 →
DuckDB/SQLite 连接创建 → `init_all_schema`（10GB 库上执行幂等 DDL）→
浏览器打开 → uvicorn 绑定。**主要耗时推定**：Python 解释器 + FastAPI/uvicorn/
duckdb 导入（1.5~3s）+ DuckDB 打开 10GB 文件并执行 schema DDL（3~6s）。

### 2. 更新窗口可用性（reports/76 P1 已修复后的现状）

- 个股指标：0.1s 响应 + "自动更新中，数据截至 xx 日"横幅 ✅
- 国债利差：0.2s ✅

## 二、候选方案（待用户决策）

### 方案 A：筛选允许"最新完整快照"口径（推荐）

- 内容：更新期间筛选不停用，基于最近一次原子快照（如 08-11）运行，
  结果页/CSV 标注"数据截至 08-11，自动更新中"；更新完成后新筛选自动用新快照
- 优点：消除"每天禁用一小时"；快照表是原子替换的，口径一致、排名不乱
- 代价：需改 `screening_readiness` 门禁与前端提示文案；PRD §12.2"以最新数据为准"
  需用户确认改为"以最新完整快照为准（可标注）"
- 工作量：中（1 个会话内可完成 + 回归测试）

### 方案 B：加速价格抓取（降低窗口时长）

- 内容：提高并发/速率（当前受数据源限速约束，reports/57 已调优至 ~80 只/分）
- 评估：**不推荐**——上游限速是硬约束，提并发有被封风险（东财 push2 已有教训），
  且即使翻倍仍有 35 分钟窗口

### 方案 C：启动提速（目标 3~4s 出页面）

- 内容：① 用 SQLite 的 schema_migrations 版本号判断，版本一致时**跳过**
  `init_all_schema`（10GB DuckDB 上的 DDL 是主要耗时）；② DuckDB 延迟打开
  （首次读请求时才连接）；③ 浏览器在 uvicorn 绑定成功后再打开（消除 U5）
- 优点：10s → 约 3~4s；改动集中在启动路径
- 代价：schema 变更时必须正确递增版本号（纪律要求）；需回归验证空库首次启动
- 工作量：小~中

### 方案 D：打包 exe（正式使用形态）

- 内容：`build-release.ps1` 构建 `value-dashboard.exe`（含 Python 与全部依赖），
  与 `data/` 同目录双击即用；本轮已修复 akshare 缺失问题后重新构建并 smoke
- 优点：无安装门槛（解压即用）；依赖版本钉死，**不会再出现 .venv 缺包这类
  环境问题**（reports/77 N1 正是源模式特有）；适合给非开发者使用
- 代价：体积约 300~500MB；每次代码/前端更新需重新构建（数分钟）；PyInstaller
  产物可能被杀软误报；开发调试仍需源模式
- 工作量：小（脚本已存在，重建 + 实测）；但"每次改动后要重新打包"是长期流程成本

### 方案 E：start.bat 体验兜底（源模式最小编程）

- 内容：启动成功后窗口显示"服务运行中 http://127.0.0.1:8765，关闭本窗口将
  停止软件"；双击时若已在运行则只打开浏览器（已有此逻辑）；可考虑最小化运行
- 优点：几乎零成本，避免"误关窗口软件没了"的困惑
- 工作量：极小

### 方案 F：常驻托盘/后台服务（远期）

- 内容：登录自启 + 托盘图标，服务常驻，开浏览器即用（真正"像大厂"）
- 代价：工作量中~大（托盘、自启、升级、退出策略），**建议远期**

## 三、对比参考（为什么 10s ≠ 打开 B 站）

打开 bilibili 是浏览器请求远端 CDN 的静态页面（几百 KB，全球节点）；
本工具是**本地启动一个 Python 服务 + 打开 10GB 的分析数据库**（含 3,280 万行
审计表），两者不是同类。10s 的主要成分是 DuckDB 打开大库 + 幂等 DDL，
方案 C 可压缩到 3~4s；若再配合方案 F（常驻）则日常体验为"秒开"。

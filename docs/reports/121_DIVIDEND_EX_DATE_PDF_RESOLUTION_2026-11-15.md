## 1. 结论（TL;DR）

1. **脚本可安全批量跑**：v1 在"长循环 + DuckDB 连接 + HTTP/sleep"里每只股票都开一次读连接，
   正是本机 Python 3.12 `PyEval_SaveThread ... GIL released` 的组合条件。已改为**三段式**
   （只读物化 → 关连接 → 纯网络循环写 JSONL → `--apply` 单短事务），循环里不再出现任何
   DuckDB 调用。**50 只真实股票连续跑完一次没崩**，并支持 `--batch-size 50` + `--resume`
   分批复跑（每批独立进程，最稳）。
2. **解析命中率大幅提升**：同一批真实公告原文上，v1 只能解**表格版**（茅台式）**3/9**，
   深市行文版 6/9 全部返回 `None`；v2 是 **9/9**。50 只真实抽样里
   **正文取回后解析成功率 37/37 = 100%**。
3. **真实抽样（50 只 / 正式库只读）**：公告找到 **88%**、正文取回 **74%**、解析成功 **100%**、
   xdxr 一致 **67.6%**、最终可写 **74%**。
4. **失败形态 10 类可修、已全部修掉并各钉了一个真实文本单测**；剩下 3 类**不是解析问题**
   （该期根本没有分派 / 远古记录巨潮无覆盖 / B 股历史行），只能走清行或换源，不能"补"。
5. **金额核对改成软信号**：实测隔离行的 `dividend_per_share` 是**全年合计**口径
   （例：300533 隔离行 1.2 = xdxr 中期 0.7 + 年度 0.5），硬按金额否决会误杀 6.7% 的正确匹配。
6. **写库路径硬规则**（按 lead 裁决）：只有 `confidence=xdxr_confirmed` 才默认写 `dividends`；
   仅 PDF 解析的 `pdf_only` 会被 `--apply` 扣下，需人工看 JSONL 后 `--include-pdf-only` 放行。

## 2. A：让脚本可稳定批量跑

### 2.1 崩溃根因（定位到具体代码）

v1 的 `_resolve_one_stock(duck, adapter, client, item)` 在**每只股票**里调用
`_xdxr_dates(duck, ...)` → 每次 `duck.read_connection()` 开一个只读连接，与 `httpx` 请求、
`time.sleep(0.5)` 交错在同一个长循环里。这与已知必崩组合（长循环 + DuckDB 连接 + HTTP/sleep）
完全一致，所以"跑几只就崩"是可复现的结构性问题，不是偶发。

### 2.2 三段式改造

| 阶段 | 开 DuckDB？ | 做了什么 |
|---|---|---|
| 只读阶段 | ✅ 一次性 | ① 读 `dividends_quarantine`（8,467 行）② 按本轮目标股票一次性读 `xdxr` 窗口事件 ③ **立即关闭连接**（`del duck`） |
| 抓取/解析阶段 | ❌ **绝不** | 只用内存字典 + HTTP：公告搜索 → 正文取回（PDF/HTML）→ 纯文本解析 → 校验 → 逐行 append JSONL（每行 flush） |
| 应用阶段 | ✅ 一次短事务 | 读 JSONL → 备份 → 写锁检查 → 单事务写 `dividends` + 删隔离行 |

关键实现点：
- `_load_xdxr()` 用**一条**`IN (...)` 查询把本轮股票的除权事件装进内存字典，循环里只做字典查找；
- `_resolve_stock()` / `_pick_for_row()` **签名里没有 store 参数**（结构上就拿不到连接）；
- JSONL 逐行 append + `--resume`：进程随时可以死，已完成的 `(stock_code, placeholder_date)` 不重做。
- 可复核证据：把"抓取/解析阶段"整段代码 grep `duck|read_connection|read_query|transaction|connect`
  → **零命中**（`source_db` 溯源字符串已移到循环之前）；全文件只剩 5 处 DuckDB 调用点：
  `_backup_tables`(720) / `_apply_plan`(737) / `_run_apply`(897) / `_run_fetch` 只读阶段(922,924)。

### 2.3 新增/变更 CLI

```
--out <jsonl>        抓取/解析模式（默认 .planning/dividend-ex-dates/plan.jsonl）
--apply <jsonl>      应用模式：一次短事务写库（需 --yes）
--stats <jsonl>      只读统计：公告找到/PDF 下载/解析成功/xdxr 一致/最终可写 + 状态分布
--resume             按 JSONL 已有 (stock_code, placeholder_date) 跳过（分批续跑）
--batch-size N       单次进程最多处理 N 只（默认 50，跑满即退出并打印"还有 N 只未处理，请再跑一次"）
--limit N            本轮按占位日从新到旧取 N 只（0=全部）
--sample N --seed S  随机抽样 N 只（可复现，做命中率证据用）
--latest-only        每只股票只处理最近的占位行（抽样/试点）
--sleep S            每只股票之间的间隔（默认 0.5s，源侧限速）
--include-pdf-only   --apply 时额外放行无 xdxr 佐证的 pdf_only 条目
--yes                写库显式确认
```

### 2.4 写库安全（`--apply`）

1. **只读保证**：`--out` / `--stats` 全程只读（读连接 `read_only=True`）；`--apply` 才写。
2. **备份**：写前 `COPY dividends TO parquet` + `COPY dividends_quarantine TO parquet`
   到 `.planning/maintenance-backup-resolve-dividend-ex-dates-<时间戳>/`，并把 plan.jsonl 一起复制进去。
3. **写锁检查**：`exclusive_update()` 应用级锁；被自动更新持锁时退出码 3 并提示稍后重试。
4. **再校验**：每条 entry 在写之前重新验一遍（占位日→除权日间隔 0–400 天、公告日不晚于除权日），
   不合法就 `rejected` 计数并跳过（防手工编辑 JSONL 写入离谱日期）。
5. **来源库一致性**：JSONL 每行带 `source_db`，`--apply` 时若与目标库不一致直接拒绝。
6. **幂等**：隔离行已不存在 → `quarantine_missing` 跳过；`dividends` 已有该 `ex_date` → `already_present`，
   只删隔离行。重复 apply 不会重复写。
7. **软信号金额核对**：公告每股现金与隔离行 `dividend_per_share` 偏差 >50% 时只标
   `amount_match=false`，**不否决**（原因见 §4 形态 #10）。

### 2.5 验证证据（临时库，不回写正式库）

同一份代码在临时库上跑完整链路（3 只真实股票 + 2 条 xdxr 种子）：

```
--out    → resolved 3（xdxr_confirmed 2 / pdf_only 1），no_announcement 1
--apply --yes                        → inserted 2, quarantine_deleted 2, pdf_only 1 条被扣下
--apply --yes --include-pdf-only     → inserted 1, quarantine_missing 2（前两条已处理，幂等）
库内 dividends   : 000001 2025-06-12 / 300750 2026-08-10 / 600519 2025-06-26（含 quarantine 的 dps 一起带过来）
库内 quarantine  : 只剩无法解析的 000002
```

正式库上 `--out` 也一次跑通 50 只（见 §3），**没有出现 GIL 崩溃**。

## 3. B：真实抽样命中率（正式库只读 + CNINFO 真实 PDF）

  → 8,467 行 / 2,436 只（与任务书一致）；`xdxr` 184,486 行 / 5,548 只；`dividends` 57,979 行。

- 每只：CNINFO 公告搜索（先 `category_qyfpxzcs_szsh` 权益分派类别，没命中再放宽全类别）

## 5. 解析器 v2 的关键设计（为什么会更准而不是更松）

1. **关键词链归属**：从每个日期**向左**吃掉紧邻的「连接词（为/是/：/及/和/与/、）+ 关键词」链，
   链上有哪些标签，这个日期就归属哪些标签。`除权除息日及现金红利发放日为 D` → D 同时是除权日和派发日；
   小标题 `股权登记日与除权除息日` 后面跟的是正文，链在正文处断开，**不会串位**。
2. **跨行规则**：允许跨**一行**，但**上一行必须自带日期**（说明是同一句被折断）。这条规则同时挡住了
   "表头行 + 数据行"（上一行没有日期）被误判成"登记日=除权日"的情况。
3. **三分支兜底**：① 带 `A/B 股` 标签的表格 ② 行文版 ③ 无标签表格（表头 + 数据行）。都失败返回 `None`。
4. **绝不猜**：`ex_date` 缺失一律 `None`；登记日与除权日相隔 >60 天则弃用登记日；派发日早于除权日则弃用。

单测：`tests/regression/test_dividend_pdf_parser.py` **26 passed**（v1 是 8 个），其中
**8 个直接用真实公告原文**（茅台表格 / 平安银行 / 宁德时代 ×3 / 德科立 / 西部证券 / 洪都航空 /
柳工 GBK HTML 页），另有 1 个 A/B 股行序的合成样本与若干合成边界用例。

## 6. C：依赖说明（pypdf 未进锁文件）

- 现状：`.venv` 里已有 `pypdf 7.1.0`（手工 `pip install pypdf`），但 `pyproject.toml` / `uv.lock`
  **没有登记**；本机无法访问 PyPI，`uv lock` 失败，所以本轮**没有联网加依赖**。
- 脚本顶部 docstring 已写明：
  > 启用方式：联网后执行 `uv add pypdf && uv lock`；未安装时脚本不会静默降级，
  > 会打印 `解析分红公告 PDF 需要 pypdf：联网后执行 uv add pypdf && uv lock …` 并以退出码 4 结束。
- 代码里是**惰性导入 + 显式报错**（`PdfSupportUnavailable` → 退出码 4），且该异常**不会被单份 PDF
  的失败兜底吞掉**（`_BodyTextCache` 里显式 `raise`）。解析逻辑本身不依赖 pypdf，单测全部离线可跑。

## 7. 正式库执行命令与预计写入行数

### 7.1 命令（按顺序；A1/A2 只读，A3 才写）

```bash
# A1 试点：25 只随机抽样（只写 JSONL，不碰库）
python scripts/resolve_dividend_ex_dates.py \
  --out .planning/dividend-ex-dates/plan.jsonl \
  --sample 25 --seed 20261115 --latest-only --sleep 0.5

# A2 全量分批：每批 50 只、跑满即退出（每批一个独立进程，最稳）
#    反复执行同一命令 + --resume，直到打印"还有 0 只未处理"
python scripts/resolve_dividend_ex_dates.py \
  --out .planning/dividend-ex-dates/plan.jsonl \
  --batch-size 50 --resume --sleep 0.5

# A2' 看命中率与状态分布（只读）
python scripts/resolve_dividend_ex_dates.py --stats .planning/dividend-ex-dates/plan.jsonl

# A3 写库：备份 + 写锁检查 + 单事务；默认只写 xdxr 佐证条目
python scripts/resolve_dividend_ex_dates.py \
  --apply .planning/dividend-ex-dates/plan.jsonl --yes

# A4 人工过一遍 JSONL 里 confidence=pdf_only 的条目后，显式放行（可选）
python scripts/resolve_dividend_ex_dates.py \
  --apply .planning/dividend-ex-dates/plan.jsonl --yes --include-pdf-only
```

> 执行前需要：`VD_ENV=formal VD_FORMAL_ACK=confirmed` + `VD_DUCKDB_PATH`/`VD_SQLITE_PATH`
> 指向 `data/valuedashboard.duckdb` / `.sqlite`；**自动更新/其他写入进程必须空闲**
> （Windows 下 writer 持锁时只读连接也打不开，脚本会报"另一个程序正在使用此文件"）。

### 7.2 预计写入行数
